# Changelog

## 1.0.0

The first release of the fork. Compared with box2d3-wasm 5.2.0, from which it was forked:

- **Generated bindings.** `scripts/gen-bindings.mjs` reads Box2D's headers as clang's AST and writes `csrc/generated.cpp`: every enum, every struct that carries no pointer as an embind `value_object`, every function whose signature needs no help. The hand-written part (`csrc/glue.cpp`) is only what a generator cannot do: callbacks, arrays, strings, events, out-parameters, debug draw and user data. A function that is neither generated, hand-written nor listed as excluded fails the build.
- **Plain objects.** Structs cross as JavaScript objects by value, in both directions. There is no `.delete()`, no `new B.b2Vec2()`, no `.Set()`: `{ x, y }` is a vector. Every struct with a `b2Default*` function is a definition: it comes out whole and goes in as any subset of its fields, nested definitions included; a missing field keeps its C default. Array counts are clamped to the array's capacity.
- **Exceptions never cross wasm.** Every callback is called through a guard that keeps what it throws and gives Box2D a terminating answer; every export is wrapped to throw the kept error once the call has returned and to restore the stack pointer when embind's own conversion errors unwind through it. Upstream let a throwing callback unwind through wasm, which leaked the shadow stack on every throw and corrupted the heap after a few dozen. `b2DestroyWorld` refuses to run inside the world's own callbacks.
- **Typed declarations.** `box2d.d.mts` is written from the same data that made the bindings: the parameter names, the definition structs and their input types, the hand-written signatures, the array fields, and the doc comments of Box2D's headers on every function, struct, field and enum value. No `any` at all, against 46 before, and no post-processing of Emscripten's output.
- **One build.** A single single-threaded SIMD build. There is no runtime choice between a "deluxe" and a "compat" module, no pthreads, and no need for cross-origin isolation headers.
- **64-bit integers are numbers.** Collision masks and user material ids cross as doubles (exact up to 2^53); `UINT64_MAX` comes back as 2^64 and goes in again as `UINT64_MAX`, and a negative number converts as C converts a signed integer. Upstream truncated them to 32 bits on the way out.
- **Additions and completions.** `b2World_CollideMover` reports `b2PlaneResult.point`; `b2Body_GetShapes`, `b2Body_GetJoints`, `b2Chain_GetSegments` and the contact and sensor data functions return arrays; `b2World_SetPreSolveCallback` and `b2World_SetCustomFilterCallback` keep the function for the world, take `null` to clear it and drop it with the world; `b2World_Draw` takes a JavaScript object of flags and `Draw*` methods, `forceScale` and `jointScale` included; move and joint events carry the integer user data; `b2ShapeDistance`, `b2GetLengthAndNormalize`, `b2Body_ClearForces` (declared without C linkage in the pinned header) and the id packers are bound; `getMemoryStats` reports the heap; `*_SetUserDataInt`/`*_GetUserDataInt` stand in for the raw user-data pointers.
- **A bug of the old glue fixed.** Upstream's `b2ChainDef.SetMaterials` never applied the materials: every chain segment had friction 0 and restitution 0 whatever was given. The fork applies them, so a simulation with chains differs from one run on the old package.
- **Tests and CI.** A node:test suite for the binding's contract (definitions, callbacks, arrays, events, exceptions, re-entrancy, recycled worlds, leaks, reproducibility, the debug variant), a compiled type check of the declarations, and a workflow that builds both variants on every push, fails if the committed artifacts differ from what the sources produce, and runs both checks. The artifacts are reproducible across machines.
- **Box2D** stays at the commit box2d3-wasm 5.2.0 pinned (`3a4f0da`, reporting 3.2.0), so simulations match apart from the chain materials.
